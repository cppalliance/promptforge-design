# Prompt Enrichment Algorithms for Long-Horizon Coding Agents

*Report type: informational / status survey, organized by topic (rulebook sections 2.1 and 4.1). It records the state of the art and flags evidence quality; it does not recommend a course of action.*

## Executive summary

Five algorithm families account for nearly all prompt enrichment in production long-horizon coding agents: context compaction, retrieval and grounding, planning and decomposition, verification feedback loops, and system-prompt engineering. Compaction is the most load-bearing: every production agent studied (Claude Code, Cursor, Codex, Gemini CLI, OpenHands) implements threshold-triggered summarization, and Cursor reports that training the model to summarize itself cuts compaction error by 50% at one fifth the tokens compared with prompt-based compaction (vendor-reported, no public benchmark). Retrieval is the second pillar: Aider's repo map (tree-sitter plus personalized PageRank) and Cursor's embedding index (vendor-reported +12.5% Q&A accuracy) are the canonical designs. Planning, reflection, and verification loops carry the strongest academic evidence, with Reflexion lifting HumanEval pass@1 from 80% to 91% over a GPT-4 baseline (paper-reported) and Agentless reaching 32.0% on SWE-bench Lite at $0.70 per issue. Two honest caveats frame everything below. First, most benchmarks measure single-problem repair, not multi-hour trajectories; the long-horizon evidence base is thin. Second, production internals are known mainly through vendor blogs and unofficial source mirrors, so several specific constants cited here are consistent across mirrors but not officially confirmed.

## 1. Method

Five parallel web-research agents ran roughly 50 searches in total, one agent per algorithm family. Each agent was instructed to prefer primary sources (arXiv papers, official documentation, lab engineering blogs), to capture a URL, date, and verbatim quote per claim, and to report evidence gaps. Their collected data is retained in five research files dated 2026-09-11 (context compaction, retrieval grounding, planning decomposition, reflection verification, system prompt design). This report synthesizes those files; every load-bearing claim carries a source, and source quality is characterized as peer-reviewed, vendor-reported, or unofficial where it matters. Where a number could not be verified against a primary source, it is flagged rather than smoothed over.

## 2. Compaction decides what survives the context window

Every production long-horizon agent treats the context window as a managed resource, and the managing algorithm is some form of triggered summarization. The designs differ in what triggers compaction, what survives it, and whether the raw history stays reachable.

**Threshold-triggered summarization is the industry default.** Claude Code fires auto-compaction when the transcript approaches the effective window minus a roughly 13K-token buffer (about 167K tokens for a 200K-window model), reserves up to 20K tokens for the summary, and trips a circuit breaker after three consecutive compaction failures. These constants come from unofficial source mirrors and third-party deep dives, consistent across mirrors but not published by Anthropic. Anthropic does publish its server-side variant: the `compact_20260112` API compaction with a configurable `input_tokens` trigger (minimum 50K, default 150K), and a companion mechanism called context editing (`clear_tool_uses_20250919`) that prunes rather than summarizes, clearing the oldest tool results past a trigger while keeping the last N tool pairs. Anthropic reports 84% token reduction in a 100-turn web-search evaluation from context editing; the figure is first-party and self-reported, with no public methodology.

**Training the model to compact itself beats prompting it to.** Cursor trains its Composer model with compaction in the reinforcement-learning loop, so the summary itself receives reward signal. Cursor reports 50% lower compaction error at roughly one fifth the tokens of prompt-based compaction, with fixed triggers at 40K and 80K tokens and summaries near 1,000 tokens. This is vendor-reported with no public benchmark, but it is the clearest statement found of where the field is heading: compaction as a trained capability, not a prompt trick. Cursor pairs this with dynamic context discovery, where history, terminal output, and tool results live as searchable files, so a post-compaction agent can grep back details the summary dropped.

**Academic work supplies the design space.** MemGPT (arXiv:2310.08560) frames context as an operating-system memory hierarchy: main context, recall storage, and archival storage, with the agent issuing paging function calls, an eviction warning at 70% capacity, and a forced recursive-summary flush at 100%. OpenHands implements the same idea as its LLMSummarizingCondenser: keep the head and the recent tail, summarize the middle into a Condensation event, and never delete the raw event log. SelfCompact (arXiv:2606.23525) lets the model decide when to compact through a compaction tool plus a rubric (fire at subtask resolution, suppress mid-derivation), reporting gains of 18.1 points on math and 5 to 9 points on agentic search at 30 to 70% lower cost than fixed-interval triggers. The consistent design principle across all three: summarize the middle, preserve the ends, and keep raw history addressable.

**Cache economics constrain every compaction design.** Manus reports roughly 100 input tokens per output token in agent workloads and calls KV-cache hit rate "the single most important metric"; Anthropic's pricing makes the stakes concrete, with cache reads at 0.1x base input price and writes at 1.25x to 2x. Anthropic reports a 100K-token prompt's time-to-first-token falling from 11.5 seconds to 2.4 seconds under caching. A compaction event invalidates the cached prefix, which is why Anthropic's context editing protects cache economics with a `clear_at_least` floor and why Claude Code's decompiled prompt assembly isolates volatile content behind a cache-boundary marker (section 6).

## 3. Retrieval injects the repository into the prompt

Retrieval algorithms answer the question compaction cannot: what code should enter the prompt in the first place. Three production designs dominate, and the academic literature adds chunking and selection algorithms with real benchmark numbers.

**Aider's repo map is the canonical graph algorithm.** It extracts definitions and references with tree-sitter, builds a file-level directed multigraph, runs personalized PageRank biased toward chat files (50x), mentioned identifiers (10x), and specific long identifiers (10x), then binary-searches the ranked list to fit a token budget that defaults to `max(1024, min(max_input_tokens/8, 4096))`. The full algorithm is published in Aider's source and a 2023 blog post, making it the most reproducible production retrieval design found.

**Embedding indices serve semantic queries; keyword search still does the work.** Cursor indexes codebases with local semantic chunking, a custom server-side embedding model, vectors in Turbopuffer, and a Merkle tree of file hashes so only changed chunks re-embed. Cursor reports semantic search lifts Q&A accuracy by 12.5% on average (6.5 to 23.5% by model) and, in a production A/B test, +2.6% code retention on repositories over 1,000 files; these are vendor figures on an internal benchmark. Sourcegraph's Cody runs a two-stage retrieve-then-rank pipeline that fuses Zoekt trigram keyword search, embedding search, and a code graph. The sobering datum comes from Sourcegraph's CodeScaleBench: agents invoked keyword search 4,813 times against 587 natural-language calls, and used a deep-search tool only 8 times in 602 runs. Agents default to lexical search even when semantic tools exist, so the enrichment layer must work with grep-grade behavior, not against it.

**Chunking and selection algorithms carry the peer-reviewed gains.** cAST (arXiv:2506.15655) chunks code by recursive split-then-merge over tree-sitter ASTs and reports +4.3 points Recall@5 on RepoEval and +2.67 points Pass@1 on SWE-bench over line-based chunking. RepoCoder (arXiv:2303.12570) closes the retrieval-generation loop by using the model's own previous completion as the next query, gaining over 10% on RepoEval settings. RepoFormer (arXiv:2403.10059) trains the model to abstain from retrieval when it will not help, reporting up to 70% inference speedup without accuracy loss. Agentless (arXiv:2407.01489) shows the ceiling of pure localization: hierarchical file-then-element-then-line ranking reaches 69.7% file-level accuracy and underpins its 32.0% SWE-bench Lite result. The pattern across these papers is that retrieval quality, not retrieval volume, drives the gains.

## 4. Planning algorithms decompose the horizon into prompt-sized steps

Planning prompts convert a task too long for one context into a sequence of prompt-sized units. The academic lineage is short and well measured; the production practice is wider and barely measured.

**ReAct is the base pattern under nearly every coding agent.** Interleaving thought, action, and observation (arXiv:2210.03629) lifted absolute success by 34 points on ALFWorld and 10 on WebShop over imitation and reinforcement baselines, and every agent loop studied here is a ReAct descendant. Tree of Thoughts (arXiv:2305.10601) adds search over reasoning paths, reaching 74% on Game of 24 where chain-of-thought scored 4%. LATS (arXiv:2310.04406) runs Monte Carlo tree search over ReAct trajectories and reports 92.7% HumanEval pass@1 with GPT-4. These are peer-reviewed results, but on single problems; none measures a multi-hour trajectory.

**Orchestrator-workers is the production decomposition pattern.** Anthropic's engineering guidance describes a central model that decomposes the task at runtime and fans out to workers, with an evaluator-optimizer loop for verification. Anthropic reports its multi-agent research system beat single-agent Opus 4 by 90.2% on an internal research evaluation, that token usage explains 80% of BrowseComp variance, and that subagents return 1,000 to 2,000 token summaries from tens of thousands of tokens explored. All first-party and self-reported. The mechanism matters more than the number: fan-out is a prompt-enrichment technique, because each worker returns a compressed, task-shaped context to the orchestrator.

**Scaffolding quality is a first-order variable, not a detail.** A 2026 leaderboard comparison (secondary source) puts the same Claude Sonnet 4.5 at 43.2% on SWE-bench Verified under SWE-agent's scaffold and 59.8% under Cline's, a roughly 16-point gap attributable to orchestration alone. SWE-agent's own ablation supports the direction: its deliberately designed agent-computer interface adds 10.7 points over a shell-only baseline (arXiv:2405.15793). CodeAct (arXiv:2402.01030) reports up to 20% higher success from consolidating actions into executable code rather than JSON or text, across 17 models.

**The popular practice layer has almost no controlled evidence.** TODO-list prompting, plan files, checkpoint-and-resume prompts, and spec-driven pipelines (GitHub Spec Kit, Amazon Kiro: spec to plan to tasks to implement) are documented only in vendor blogs and community writeups. No peer-reviewed quantification of plan-file prompting was found. This is the largest gap between what practitioners do and what the literature measures.

## 5. Verification loops turn tool feedback into prompt signal

Verification algorithms enrich the prompt with evidence about the agent's own last action: test output, compiler errors, critic verdicts. The academic evidence here is the strongest in this report, and it comes with an important counter-finding.

**Verbal self-reflection works when grounded in external feedback.** Reflexion (arXiv:2303.11366) stores verbal lessons in episodic memory instead of updating weights and reports 91% HumanEval pass@1 against an 80% GPT-4 baseline. Self-Refine (arXiv:2303.17651) alternates feedback and refine prompts in one frozen model for roughly 20% average absolute improvement across seven tasks. CRITIC (arXiv:2305.11738) motivates the loop from the finding that models cannot reliably validate their own output, so tool output supplies the critique. Self-Debugging (arXiv:2304.05128) teaches rubber-duck debugging few-shot, gaining up to 12 points on TransCoder and MBPP when unit tests exist. AlphaCodium (arXiv:2401.08500) calls the whole approach flow engineering and lifts GPT-4 pass@5 on CodeContests validation from 19% to 44%, treating public tests as trusted anchors.

**Intrinsic self-correction without external grounding can hurt.** On GSM8K, intrinsic self-correction dropped GPT-4 from 95.5% to 89.0% (arXiv:2310.01798), and human feedback beat GPT-4 self-feedback by 1.58x on repair success (arXiv:2306.09896). LLM-as-judge agrees with execution ground truth at only kappa 0.21 on Java and 0.10 on Python (arXiv:2507.16587). The defensible reading of the literature: enrich prompts with execution feedback, not with the model's unaided opinion of itself. Confidence in this reading is moderate; the studies are peer-reviewed but on single-problem benchmarks.

**Long-horizon failure modes have names but thin evaluations.** SWE-agent's trajectory analysis (the closest thing to long-horizon quantitative evidence found) shows 51.7% of trajectories contain at least one failed edit, and edit success falls from 90.5% to 57.2% after one failure. Frameworks respond with stuck-state detectors: OpenHands, PraisonAI, and LongGuard name patterns like repeating action-observation cycles and ping-pong alternation, with graduated recovery ladders from nudge to human handoff. None of these detectors has a peer-reviewed evaluation. A 2026 benchmark, HiL-Bench, adds a sharp finding: frontier agents score 75 to 89% with full information but collapse to 4 to 24% when they must detect ambiguity and ask for help themselves, and harness scaffolds were found to actively suppress escalation. Asking-for-help is an unsolved prompt-enrichment problem.

## 6. System-prompt engineering is cache economics plus instruction hierarchy

The system prompt is the one enrichment channel that is always present, and production practice treats it as an engineering artifact with a cost model.

**Prompts are assembled static-first to protect the cache.** Claude Code's guidance and its decompiled assembly logic agree on the shape: static system prompt and tool definitions first (globally cached), then project context such as CLAUDE.md, then session context, then conversation, because any byte change in a prefix invalidates everything after it. The decompiled source shows a literal `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` marker splitting the cached prefix from memoized dynamic sections, with an escape hatch for volatile MCP instructions. The decompilation is unofficial; Anthropic's own blog confirms the principle and the economics, with reported input-cost reductions up to 90% for agents reusing a fixed system prompt and tool schema.

**Tool descriptions are a prompt-engineering surface.** Anthropic's tooling guidance prescribes being explicit about when to call a tool, naming parameters unambiguously (`user_id`, not `user`), and using strict schemas for grammar-constrained inputs. SWE-agent formalized the same idea as the agent-computer interface: bounded search, a 100-line windowed viewer, lint-checked edits, concise feedback. Cursor's production finding, reported through OpenAI's GPT-5 prompting guide, is that structured XML instruction specs improved instruction following and cross-referencing within the prompt.

**Instruction hierarchy is moving from prompt text into training.** OpenAI trains models on a System > developer > user > tool precedence order, which improves robustness to instructions embedded in tool outputs. The motivation is concrete: a 2026 systematization-of-knowledge paper covering 78 studies reports over 85% adaptive-attack success against state-of-the-art prompt-injection defenses, with most of 18 surveyed defenses under 50% mitigation. Deterministic defenses like Microsoft's FIDES (information-flow labels propagated by middleware and enforced before tool execution) represent the engineering response: do not ask the prompt to do what the harness must guarantee.

## 7. Limitations and evidence gaps

This survey's conclusions rest on uneven evidence, and the unevenness is itself a finding. Peer-reviewed results cluster on single-problem benchmarks (HumanEval, MBPP, SWE-bench instances); almost nothing measures multi-hour trajectories, so the phrase "long-horizon" in the literature usually means "longer than one prompt," not "hours." Production internals are known through vendor blogs (self-reported numbers, no public methodology) and unofficial source mirrors (consistent but unconfirmed constants). No vendor publishes a full production system prompt; all complete texts come from leaks of unverifiable freshness. Specific gaps: token-budget allocation across prompt components is documented only for Aider; code-specific reranker benchmarks do not exist publicly; TODO-list and spec-driven practice have zero controlled evaluations; stuck-loop detectors have none either; and OpenAI publishes strikingly little agent context-management guidance compared with Anthropic. Where this report cites a number, the surrounding text states who measured it.
